=== RUNTIME CRASH FIX (5th pass) - particles now spawn ===
==========================================================
CONFIRMED: particles now spawn in-game (CascadeParticle appeared near water).

Crash: ArrayIndexOutOfBoundsException in CascadeParticle.tick
  ParticleSpriteManager$SimpleSpriteProvider.getSprite -> Index 12 out of bounds for length 12
  CascadeParticle at Age 10, maxAge 9, cascade.json has 12 sprites (0..11).
Root cause: CascadeParticle.tick() called super.tick() (which increments age to
10 and marks the particle dead when age >= maxAge), then UNCONDITIONALLY called
getSprite(age=10, maxAge=9) => index age*(size-1)/maxAge = 10*11/9 = 12 -> OOB.
The original 1.16 selectSpriteWithAge guarded with an isExpired check; that guard
was lost in the port.
Fix: guard the sprite update with isAlive() after super.tick():
    super.tick();
    if (!this.isAlive()) return;
    this.removeIfInsideSolidBlock();
    if (this.isAlive()) this.setSprite(this.provider.getSprite(this.age, this.maxAge));
Other age-based particles (WaterRipple/WaterSplash/WaterSplashRing) already guard
via `if (this.age++ >= this.maxAge) { markDead(); return; }` so age never exceeds
maxAge when getSprite is called — they were already safe.

=== RENDER ORIENTATION FIX (6th pass) - flat particles ===
==========================================================
Screenshot showed water splash/foam rendering as GIANT WHITE SQUARES facing the
camera (wrong). Root cause: default BillboardParticle rendering = camera-facing
square quad, but the original renders ripples/rings/splash-foam as FLAT quads on

return a rotator that lays the quad flat (rotationX(PI/2)):
- WaterRippleParticle: flat
- WaterSplashRingParticle: flat
- WaterSplashParticle (+ WaterSplashFoamParticle inherits): flat
- LeafParticle: flat when expiring (settled on ground), ALL_AXIS (camera-facing)
  while falling so the sway (zRotation) still reads correctly.

getRotator() must be declared `public` (superclass declares it public; a weaker
`protected` fails to compile: "attempting to assign weaker access privileges").

NOTE / honest limitation: the original WaterSplash/Foam is a vertical 3D "crown"
(4 stacked vertical faces). The 1.21.11 billboard submittable can only draw single
square camera-oriented quads, so a perfect 3D crown is not reproducible via the
public particle API. Flat-on-water discs are the closest faithful approximation
and eliminate the giant-square artifact. Ripples/rings/settled-leaves ARE flat in
the original, so those now match. Falling leaves + fireflies + cave dust + waterfall
spray use camera-facing billboards (same as originals which were camera-facing sprites).

=== LAG ROOT CAUSE + FIX (7th pass) ===
==========================================================
Reported: stuttering on the "Загрузка территории..." (DownloadingTerrain) screen.

ROOT CAUSE (introduced by the runtime driver): emitRandomDisplayTicks runs 1334
iterations every client tick. Each iteration allocated a fresh BlockPos via
mutable.toImmutable() (=1334 allocs/tick), and updateCascade — called for EVERY
water block — allocated ~1-10 BlockPos per call (pos.up()/down()/north()/...).
In a water biome (the swamp/ocean in the screenshot) that's thousands of BlockPos
allocations per tick -> heavy GC churn. During terrain streaming the client is
already GC/CPU-bound (chunk gen + meshing), so the extra churn shows up as stutter
specifically on that loading screen.

FIX:
1. randomDisplayTickAt: pass the shared BlockPos.Mutable directly to handlers
   instead of toImmutable() (handlers read immediately or copy). Removes 1334
   allocs/tick.
2. updateCascade: rewritten to use a shared static BlockPos.Mutable (CASCADE_NEIGHBOR)
   for all neighbour getFluidState/getBlockState lookups. Removes ~all per-water-block
   allocations. Behaviour identical.
3. Warmup guard: skip the heavy emission loop for the first WARMUP_DURATION (60)
   ticks (~3s) after join / dimension change, so it doesn't run while terrain is
   still streaming (the loading screen). Reset in clear() and on dimension change.
   (Chose a tick-based warmup instead of `instanceof DownloadingTerrainScreen`
   because that class is not at net.minecraft.client.gui.screen in 1.21.11 Yarn.)

=== TRUE 3D WATER CROWN (9th pass) ===
==========================================================
Screenshot confirmed effects work (ring/ripple flat = correct), but water splash/
foam were flat billboards, not the original 3D "crown".

KEY TECHNIQUE (stays inside the vanilla particle pipeline, low risk): override
BillboardParticle.render(BillboardParticleSubmittable, Camera, float) and call
submittable.render(...) FOUR times with fixed WORLD-space rotations to build a box
"crown" from 4 vertical faces:
- 2 faces in the XY plane (identity quaternion), at z±w
- 2 faces rotated 90 about Y (rotationY(PI/2)), at x±w
Each face is a square of half-size w = width*(0.8+0.2*progress), centred at
wallCenterY = cy + w so the base sits on the water surface. Uses the sprite UVs
(getMinU/MaxU/MinV/MaxV), packed colour via ColorHelper.fromFloats(alpha,r,g,b),
brightness via getBrightness, and getRenderType(). WaterSplashFoam inherits this
(white crown). This reproduces the original cylinder-crown look.

submittable.render signature (verified compiling):
  render(RenderType, x, y, z, rotX, rotY, rotZ, rotW, size, minU, maxU, minV, maxV,
         int color, int brightness)
Camera position accessor in 1.21.11 = camera.getCameraPos() (NOT getPos()).
